# FTIR cinematic 项目协作原则

## 目标与依据

- 面向有基本自然科学背景、首次认真学习 FTIR 的观众。目标是让观众解释仪器与数学步骤分别解决什么测量问题，并能预测主要变化；采用科学可靠的教学模型，不默认建设科研级仿真软件。
- 以现有 cinematic 影片及有效 motion assets 为视觉基础。核实实际入口与调用链：`src/remotion/FTIRFilm.tsx`、`src/timeline/filmTimeline.ts`、相关 scene 与数学模块。以运行配置为准，过时注释、历史计划与独立 review composition 不代表当前主片。
- 用户最新授权与反馈优先。具体分镜、时长、教学数据、冻结范围和本轮 agent 安排写入制作计划，不固化为永久规则。相邻项目的协作文件不自动适用于本项目。

## Science-explainer 决策原则

- 引入概念前建立认知需求：观众当前想知道什么，已有方法为什么不能回答，这个概念怎样推进答案。可以用现象、比较、失败尝试或预测建立需求，不强制每幕出现文字问句。
- 不止解释 WHAT happens，继续解释 WHY it matters for the measurement。物理差异应兑现为可观察、可利用的测量信息；不能把中间变量或仪器名称当作解释终点。
- 区分一个固定测量状态下的总响应与扫描获得的一系列响应。前者通常不能确定光谱组成；后者可通过受控变化保留可分析的成分规律。不得把这个困难说成探测器不够聪明，或把干涉仪说成更高级探测器。
- 叙事顺序可不同于物理光路顺序。尽早建立测量目的，但揭示机制时保持真实拓扑；概念先后应由理解需要决定，而非教材目录或既有 Act 边界。
- 优先用问题、现象、比较与连续运动建立直觉，再命名与概括。公式可以帮助理解，但应压缩已有直觉，不能代替缺失的解释。
- 新 representation 必须解决明确的理解问题。引入前评估读图成本；避免为展示专业性而把同一关系依次换成多套图。相位、相量与详细推导按教学价值进入主片或辅助解释，不预先全面禁止。
- 深入浅出的验收包括解释、预测与迁移：观众能说明目的、预测参数变化的影响，并把本幕结果用于下一问。字幕关闭时主要因果仍应可辨；必要标签与简洁旁白可以承担命名和模型边界。

## 科学硬约束与模型边界

- 区分物理过程、观察性展开、理想化模型、合成教学数据与实测参考数据。位移放大、运动放慢和坐标缩放不改变底层参数；在可能造成误解时说明，不默认堆叠常驻小字。
- 红外活性与振动引起的偶极矩变化有关；永久偶极矩不是必要条件。吸收还涉及频率匹配。分子振动比较不得偷换分子或模式身份。
- 经典透射 FTIR 的光路保持光源 → Michelson → 样品 → 探测器。分束器分出两条光路，不按波数分成独立通道；每条臂仍含宽带成分。概念性成分展开不是实际空间分光，也不是多个物理探测通道。
- OPD 是两臂光程之差。正入射、空气近似下镜位移满足 Δδ = 2Δx；写 δ = 2x 时需具有兼容的零点约定。区分 x、δ、光频率与波数，计算单位一致。
- 理想模型中同一成分的相位差按 φ = 2πν̃δ 演化。移动镜改变 OPD，不改变该成分的波数。同一 OPD 扫描中，不同波数对应不同空间调制周期；若用时间节奏表达，必须使用同一扫描驱动，不能用各自不同播放速度制造差异。
- 两臂同一波数组分的电场叠加决定其探测功率，P ∝ |E₁ + E₂|²。普通宽带探测模型将不同波数的强度调制贡献相加；不得任意相加不同光频的场矢量代替这一总响应。区分电场振幅与谱强度/调制贡献权重。
- 在当前吸收教学近似中，样品削弱选定成分的贡献，保持波数与调制周期。展示吸收发生不等于样品在扫描期间不断变化；实际记录使用明确、稳定的样品状态。
- 区分非负探测功率与相对基线的带符号调制信号。负向调制与负的 Fourier 乘积不是负光强。ZPD 不等于任意曲线最大值；少量离散成分的例子不能冒充真实宽带中心峰形。
- Fourier probe 与记录使用同一 OPD/波数约定；保留带符号贡献、真实累积与归一化。谱点来自该记录计算出的系数，不能预画结果或用 abs(product) 消除抵消。有限、理想化教学投影不宣称完成实验级 FTIR 处理，也不宣称有限扫描可无条件唯一恢复任意光谱。
- Fourier 得到的样品单光束谱不能直接叫吸收谱。Background 与 Sample 顺序测量，在兼容条件与网格上分别恢复 B、S 后取 T = S/B，A = −log₁₀(T)。不把干涉图相除、不用相减冒充比值、不用分别归一化的曲线伪造 T；无效或低背景区域按所用模型处理，不凭空制造有效值。
- 教学模型已知的输入不是实际仪器已经知道的背景。切换教学示例、化学谱带或参考谱时明确交接；不能靠静默换峰位或曲线维持假连续。实测引用保留来源、材料、相态、纵轴量与处理信息；合成谱或单峰不足以确定物质身份。

## 视觉、运动与连续性

- 优先复用、重排、缩短、延伸和连接有效资产，再决定局部重做。不要为新叙事默认换成静态信息图、卡片墙或工程示意图；已有画面也不能因实现成本而免于审查。
- 延续 `src/styles/visualSystem.ts` 的语义：琥珀用于物理光/能量，青色用于测量记录/信息，克制的红色用于选定吸收特征。其他身份线索按需要使用；不只靠颜色传意，不为每个成分任意增加颜色。
- 简洁是减少无效对象与重复表示，同时让保留对象承担重要的解释运动。不要以减少运动、缩小主图或压低对比度换取极简。
- A 的变化应可观察地驱动 B，再影响 C。镜头聚焦、路径揭示、形变和转场应帮助跟踪原因与结果；不同画面淡入淡出加字幕不自动形成因果链。解释性联动可以同时出现，避免多套独立说明争夺注意力。
- 同时保持对象身份、数据身份与测量语义。成分、探测点、record、累积值和谱点的交接应可追踪；测量记录由已定义数据生成。记录已绘制的历史不能因转场而无说明改写。
- 缩放、展开、平移或坐标变换时保持正确对应；切换横轴、基线、归一化或示例时给予必要提示。教学可视化的观察轨道不得被读成实际仪器新增通道。
- 按实际视频视口检查文字、线宽、对比度与停留时间。减少重复公式、精确验证数值、小灰字和 debug 注释；保留观众理解对象所需的标签。重要中间态、转场重叠与字幕安全区域都需检查。

## 实现与审查纪律

- 以一个连续片段迭代：设计 → 小范围实现 → 实际预览/渲染 → 自审 → 调整。先检验教学和运动，再扩展范围；不凭完整分镜文档或终帧截图判断整段成功。
- 对已验证数学与 cinematic 资产先理解后复用。叙事编辑不随意重写 Fourier 教学核心；必须改模型时说明原因、接口影响与验证方式。保留用户修改和历史资产，不擅自回滚或删除。
- 用同一测量定义驱动相关视觉。Remotion 任意帧求值应确定、可跳转、与播放顺序无关；关键状态不依赖墙钟、未固定随机数或前一帧的副作用。
- 工程抽象、库选择和代码整洁服务于作品。不得为架构优雅、实现简单或交接方便牺牲教学与视觉效果；新增依赖需解决具体问题。
- 根据变更运行必要数学回归、类型检查与构建。当前 `npm run lint` 是 TypeScript 检查；检查实际 render 注册入口与导出配置，不把脚本存在等同于可用。文档修改无需无关的整片构建。
- 必须实际播放受影响片段，检查运动、构图、可读性、科学因果与对象连续性；必要时渲染复核。与既有影片比较，判断是否更易懂、是否退化为 PPT、是否过度依赖文字、运镜是否有用。测试通过和截图漂亮不能代替播放验收。
- 自审不是首次观众验证。交付区分已实现、已检查、推断与未验证，说明剩余理解风险。涉及交互或 Presentation 时另检查其真实操作流程，不将某次播放协议固定成影片规则。

## 授权与交付

- 分析、方案与实现授权分开；仅在批准范围内施工。按当前用户要求处理委派、模型选择与停止点，不从历史协作安排推断继续授权。
- 报告具体变化、教学目的、科学/数据交接、视觉证据、工程验证及剩余问题。明确推荐观看的入口或片段；达到阶段范围后停止，不自动扩展到下一章。
